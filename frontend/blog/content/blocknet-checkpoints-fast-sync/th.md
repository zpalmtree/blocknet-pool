โหนด Blocknet ใหม่ต้องตามทุกบล็อกตั้งแต่ genesis ให้ทันก่อนให้บริการกระเป๋าหรือเครื่องขุด solo Checkpoints ช่วยให้ตามทันเร็วขึ้น คู่มือนี้อธิบายไฟล์ของ bntpool.com วิธีที่ daemon ข้ามการตรวจที่ช้าที่สุดโดยยังยึดกับเชนจริง และวิธีดาวน์โหลด ตรวจสอบ และโหลดไฟล์เอง

## Checkpoints ของ Blocknet คืออะไร?

<Answer>
Checkpoints คือรายการแฮชบล็อกที่ทราบแล้ว หนึ่งรายการทุกบล็อกที่ 100 ซึ่ง bntpool.com ให้บริการเป็น checkpoints.dat โหนดตรวจว่าบล็อกที่รับตรงกับแฮชเหล่านี้ และข้ามการตรวจ proof of work กับลายเซ็นซ้ำจนถึง checkpoint สุดท้าย ทำให้ซิงก์ครั้งแรกเสร็จเร็วขึ้นมาก
</Answer>

ไฟล์เป็นข้อความธรรมดา หนึ่งคู่ `height:hash` ต่อบรรทัด บรรทัดแรก ๆ เมื่อ 25 ตุลาคม 2026 เป็นดังนี้:

```text
100:579099BE8BECF8F60817EA71C882EC061CE60C1A8CF7727F92DBEE2F49272989
200:DDFD65EC01744A61D2A41862141F60C847AC16F43B760E582F8B11A08D18C483
300:B4657F22AE0DDFB9D724138DF4BE44376E0388FFA72162FD65E968CD5AA77625
```

แต่ละแฮชคือ ID บล็อก ซึ่งเป็น SHA3-256 ของส่วนหัว Daemon ของพูลเขียนจากเชนของตนและใส่เฉพาะบล็อกที่ลึกอย่างน้อย 100 บล็อก หนึ่งร้อยบล็อกคือขอบเขต finality ของ Blocknet หรือความลึกสูงสุดที่โปรโตคอลยอมให้จัดระเบียบใหม่ ทุก checkpoint จึงอยู่ในประวัติที่ลงตัวแล้ว

เมื่อ 25 ตุลาคม 2026 เวลา 02:04 EDT ไฟล์มี 689 checkpoints ตั้งแต่ความสูง 100 ถึง 68,900 ขนาด 48,811 ไบต์ ไฟล์เพิ่มประมาณหนึ่งบรรทัดทุก 100 บล็อก หรือราวแปดชั่วโมงเมื่อบล็อกห่างกันห้านาที ดูความสูงปัจจุบันใน[หน้า Checkpoints](/checkpoints)

## โหนด Blocknet ใช้ checkpoints อย่างไร?

โหนดที่โหลดไฟล์จะใช้ความสูง checkpoint สุดท้ายเป็นเป้าหมายซิงก์เร็ว ก่อนถึงความสูงนั้น จะอาศัย checkpoints สำหรับการตรวจสองอย่างที่ใช้ทรัพยากรมากที่สุด และทำการตรวจอื่นตามปกติ:

- **Proof of work อาศัย checkpoints** แต่ละบล็อกใช้แฮช Argon2id กับหน่วยความจำ 2 GiB การคำนวณใหม่ทุกบล็อกย้อนหลังมีต้นทุนสูง และแฮช checkpoints รับรองประวัตินั้นแล้ว
- **ลายเซ็น RingCT และ range proofs ก็อาศัย checkpoints** คอมเมนต์ใน daemon ระบุว่าการตรวจ range proof ของเอาต์พุตเป็นต้นทุนเดี่ยวที่ใหญ่ที่สุดของการซิงก์ เพราะทุกเอาต์พุตมี proof รวมถึง coinbase ทุกบล็อก
- **การตรวจอื่นยังทำทั้งหมด** การเชื่อมบล็อก กฎความยาก LWMA เวลา ขนาดและรูปแบบบล็อก การใช้จ่ายซ้ำผ่าน key images และการผูกแต่ละอินพุตกับลายเซ็นยังตรวจตามปกติ เอาต์พุตและ key images ถูกลงดัชนีเหมือนเดิม การสแกนกระเป๋าและยอดจึงเหมือนซิงก์เต็ม

การข้ามตรวจใช้เฉพาะบล็อกที่ต่อจากปลายเชนปัจจุบัน และเฉพาะใต้ checkpoint สุดท้าย เมื่อผ่านความสูงนั้น โหนดตรวจทุกบล็อกใหม่เต็มรูปแบบรวมถึง proof of work

### Checkpoints ตรึงเชนที่เชื่อถือได้อย่างไร

ขณะซิงก์ไปหา checkpoint สุดท้าย บล็อกที่ความสูง checkpoint ต้องมีแฮชตรงกับไฟล์ทุกประการ หากต่างจะถูกปฏิเสธด้วยข้อผิดพลาด checkpoint mismatch เพราะมี checkpoint ทุก 100 บล็อก peer จึงพาโหนดซิงก์เร็วไปตามประวัติอื่นไม่ได้ ความสูง checkpoint ถัดไปจะเผยความต่าง

Checkpoints ยังช่วยทุกครั้งที่รีสตาร์ต เมื่อ daemon เริ่มโดยมีบล็อกบนดิสก์แล้ว จะหา checkpoint สูงสุดที่ตรงกับเชนที่เก็บไว้และตรวจซ้ำเฉพาะบล็อกหลังจากนั้น แทนการไล่ทั้งหมดตั้งแต่ genesis

## โหนดใหม่ดาวน์โหลด checkpoints อัตโนมัติไหม?

<Answer>
ใช่ เมื่อ daemon Blocknet เริ่มและโฟลเดอร์ข้อมูลไม่มี checkpoints.dat จะดาวน์โหลดจาก https://bntpool.com/checkpoints.dat โหลดไฟล์ แล้วซิงก์เร็วถึง checkpoint สุดท้าย การดาวน์โหลดเป็นแบบพยายามเท่าที่ทำได้ หากไม่สำเร็จ โหนดยังเริ่มทำงานและตรวจเชนเต็มรูปแบบต่อไป
</Answer>

ที่อยู่นี้เป็นค่าเริ่มต้นใน Blocknet core โหนดใหม่จึงใช้ไฟล์ที่ bntpool.com เผยแพร่ได้ทันที Daemon ดึงเฉพาะเมื่อยังไม่มีไฟล์ ให้เวลาคำขอ 15 วินาที และจำกัดขนาดดาวน์โหลด 32 MiB

## ใช้ checkpoints ของ bntpool.com ทีละขั้นอย่างไร?

หากต้องการดาวน์โหลดและตรวจเอง หรืออัปเดตสำเนาเก่าก่อนซิงก์ใหม่ครั้งใหญ่ ให้ทำตามนี้

### 1. หาโฟลเดอร์ข้อมูล

ไฟล์อยู่ในโฟลเดอร์ข้อมูลของโหนดข้างฐานข้อมูลเชน:

- **ตัวจัดการ `blocknet`:** `~/.config/bnt/data/mainnet/` บน macOS และ Linux และ `C:\Users\<you>\.config\bnt\data\mainnet\` บน Windows เว้นแต่ตั้ง `data_dir` ไว้
- **เรียก core โดยตรง:** `./blocknet-data-mainnet` ในโฟลเดอร์ที่ใช้เริ่ม หรือพาธที่ระบุด้วย `--data`

### 2. ดาวน์โหลด checkpoints.dat

เปิด [Checkpoints](/checkpoints) แล้วกด **Download checkpoints.dat** หรือดาวน์โหลดจากเทอร์มินัล ตัวอย่างนี้เขียนลงโฟลเดอร์ข้อมูลเริ่มต้นของ core:

```sh
curl -L https://bntpool.com/checkpoints.dat -o blocknet-data-mainnet/checkpoints.dat
```

การดาวน์โหลดทับไฟล์เดิมจะแทนที่ไฟล์ ซึ่งเป็นวิธีอัปเดตสำเนาเก่า

### 3. ตรวจ SHA-256

หน้า Checkpoints เผยแพร่ SHA-256 ของไฟล์ปัจจุบัน คำนวณแฮชสำเนาแล้วเปรียบเทียบ:

```sh
sha256sum blocknet-data-mainnet/checkpoints.dat
```

บน macOS ใช้ `shasum -a 256` แทน แฮชเปลี่ยนทุกครั้งที่พูลเพิ่ม checkpoint จึงควรเทียบกับหน้าเว็บทันทีหลังดาวน์โหลด

### 4. สุ่มตรวจ checkpoint บน explorer

ตรวจบรรทัดใดก็ได้กับ [Blocknet explorer](https://explorer.blocknetcrypto.com) เปิดหน้าบล็อกตามความสูงในไฟล์ เช่น `explorer.blocknetcrypto.com/block/68900` แล้วเทียบแฮชกับบรรทัด 68,900 เราตรวจ checkpoint สุดท้ายเมื่อ 25 ตุลาคม 2026 และพบว่าแฮชตรงกัน

### 5. เริ่มโหนด

เริ่มหรือรีสตาร์ต daemon จะอ่าน `checkpoints.dat` ตอนเริ่มและซิงก์เร็วถึง checkpoint สุดท้าย หากใช้เชลล์โต้ตอบของ core (`--cli`) คำสั่ง `load-checkpoints` จะโหลดไฟล์ให้โหนดที่กำลังทำงานและรายงานความสูงซิงก์เร็ว:

```text
> load-checkpoints
```

Checkpoints ช่วยเมื่อโหนดยังตามหลัง เมื่อเชนผ่าน checkpoint สุดท้ายแล้ว โหนดตรวจทุกบล็อกเต็มรูปแบบอยู่แล้ว ไฟล์ใหม่จึงไม่เปลี่ยนการทำงาน

## ตรวจไฟล์ checkpoints จาก script อย่างไร?

พูลเผยแพร่รายละเอียดเป็น JSON ที่ `https://bntpool.com/api/checkpoints` โดยไม่ต้องใช้ API key:

| ฟิลด์ | ความหมาย |
|---|---|
| `available` | พูลมีไฟล์ให้ดาวน์โหลดหรือไม่ |
| `url` | ที่อยู่ดาวน์โหลด |
| `entries` | จำนวน checkpoints ในไฟล์ |
| `latest_height`, `latest_hash` | Checkpoint สูงสุดและแฮชบล็อก |
| `bytes`, `sha256` | ขนาดไฟล์และ SHA-256 |
| `updated_at` | เวลาแก้ไขล่าสุดในรูป Unix timestamp |

การดาวน์โหลดมีเฮดเดอร์ `X-Checkpoint-Height`, `X-Checkpoint-Sha256` และ `ETag` ที่สร้างจากแฮช Script จึงส่ง `If-None-Match` เพื่อรับ `304 Not Modified` อย่างรวดเร็วเมื่อไฟล์ไม่เปลี่ยน:

```sh
curl -s https://bntpool.com/api/checkpoints | jq '{latest_height, sha256}'
```

คำตอบอาจถูกแคช 60 วินาที ซึ่งเพียงพอสำหรับไฟล์ที่เปลี่ยนประมาณทุกแปดชั่วโมง

<Note>
blocknetcrypto.com ระบุว่าแผนอัปเกรด Faraday จะนำ proof of work ที่เบาลงมาใช้เพื่อให้โหนดใหม่ตามเชนทันเร็วขึ้น ระหว่างนี้ checkpoints เป็นวิธีรวดเร็วในการอัปเดตโหนดให้ทัน
</Note>

## ใช้โหนดที่ซิงก์แล้วทำอะไรได้?

โหนดที่ซิงก์แล้วรองรับกระเป๋า Blocknet และ API ของโหนด และเป็นปลายทางที่ seine ใช้เมื่อขุด solo ด้วย `--mode daemon` [ขุด Blocknet กับพูลหรือ solo](/blog/th/pool-vs-solo-mining-blocknet/) ช่วยประเมินว่า solo เหมาะกับฮาร์ดแวร์หรือไม่ หากอยากขุดโดยไม่เปิดโหนด seine ใช้ bntpool.com เป็นค่าเริ่มต้น [คู่มือติดตั้ง seine](https://seineminer.com/th/blog/how-to-mine-blocknet/) พาไปถึง share แรก และ[คู่มือขุดบน bntpool.com](/blog/th/mine-blocknet-on-bntpool/) อธิบายฝั่งพูล
