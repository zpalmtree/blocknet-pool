Новая нода Blocknet должна догнать все блоки от генезиса, прежде чем обслуживать кошелёк или соло-майнер. Контрольные точки ускоряют это. Руководство объясняет содержимое файла bntpool.com, пропуск самых медленных проверок без ухода с настоящей цепи и самостоятельную загрузку, проверку и подключение файла.

## Что такое контрольные точки Blocknet?

<Answer>
Это список известных хешей блоков, по одному на каждый сотый блок, публикуемый bntpool.com как checkpoints.dat. Нода сравнивает полученные блоки с этими хешами и до последней точки пропускает повторную проверку доказательства работы и подписей. Первая синхронизация становится намного быстрее.
</Answer>

Файл текстовый: в каждой строке пара `height:hash`. Первые строки 25 октября 2026 года выглядели так:

```text
100:579099BE8BECF8F60817EA71C882EC061CE60C1A8CF7727F92DBEE2F49272989
200:DDFD65EC01744A61D2A41862141F60C847AC16F43B760E582F8B11A08D18C483
300:B4657F22AE0DDFB9D724138DF4BE44376E0388FFA72162FD65E968CD5AA77625
```

Каждый хеш — идентификатор блока, SHA3-256 его заголовка. Демон пула пишет файл из своей цепи и включает только блоки глубиной не менее 100. Сто блоков — жёсткая финальность Blocknet, максимальная разрешённая глубина реорганизации. Все точки поэтому лежат в устоявшейся истории.

25 октября 2026 года в 02:04 EDT файл содержал 689 точек от высоты 100 до 68 900 и занимал 48 811 байт. Примерно каждые 100 блоков, около восьми часов при пятиминутных интервалах, добавляется строка. Текущую высоту смотрите на [Checkpoints](/checkpoints).

## Как нода Blocknet использует контрольные точки?

После загрузки последняя высота становится целью быстрой синхронизации. До её достижения нода опирается на точки для двух самых дорогих проверок, выполняя остальные как обычно:

- **Доказательство работы опирается на точки.** Для каждого блока это Argon2id-хеш с 2 GiB памяти. Пересчитывать его для всей истории дорого, а хеши точек уже подтверждают историю.
- **Подписи RingCT и доказательства диапазона тоже.** Комментарии демона называют проверку доказательств диапазона выходов крупнейшей отдельной затратой синхронизации: они есть у каждого выхода, включая coinbase.
- **Все остальные проверки сохраняются.** Связность блоков, правило сложности LWMA, метки времени, размер и структура блока, двойные траты по образам ключей и связь входа с его подписью проверяются нормально. Выходы и образы ключей индексируются как обычно, поэтому сканирование и балансы кошелька не отличаются от полной синхронизации.

Пропуск действует только для блоков, продолжающих текущую вершину ноды, и только ниже последней точки. После этой высоты каждый новый блок проверяется полностью, включая доказательство работы.

### Как точки закрепляют доверенную цепь

По пути к последней точке любой блок на отмеченной высоте обязан иметь точный хеш из файла. Другой хеш отклоняется с ошибкой несовпадения контрольной точки. Поскольку они идут через 100 блоков, пир не может увести ноду на другую историю: следующая точка это выявит.

Точки ускоряют и перезапуски. Когда блоки уже на диске, демон находит самую высокую точку, совпадающую с сохранённой цепью, и перепроверяет только следующие блоки, не проходя всё от генезиса.

## Загружает ли новая нода точки автоматически?

<Answer>
Да. Если при запуске демона в каталоге данных нет checkpoints.dat, он скачивает https://bntpool.com/checkpoints.dat, читает файл и быстро синхронизируется до последней точки. Загрузка выполняется по возможности: если она не удалась, нода всё равно запускается и проверяет цепь полностью.
</Answer>

Этот адрес задан по умолчанию в самом Blocknet core, поэтому новые ноды сразу используют файл bntpool.com. Демон скачивает его только при отсутствии локального файла, даёт запросу 15 секунд и ограничивает размер 32 MiB.

## Как использовать точки bntpool.com пошагово?

Если хотите скачать и проверить файл сами либо обновить старую копию перед долгой повторной синхронизацией, выполните следующие шаги.

### 1. Найдите каталог данных

Файл лежит рядом с базой цепи в каталоге данных ноды:

- **Менеджер `blocknet`:** `~/.config/bnt/data/mainnet/` в macOS и Linux, `C:\Users\<you>\.config\bnt\data\mainnet\` в Windows, если не задан `data_dir` в конфигурации.
- **Прямой запуск core:** `./blocknet-data-mainnet` в каталоге запуска либо путь флага `--data`.

### 2. Скачайте checkpoints.dat

Откройте [Checkpoints](/checkpoints) и нажмите **Download checkpoints.dat** либо используйте терминал. Пример пишет в стандартный каталог core:

```sh
curl -L https://bntpool.com/checkpoints.dat -o blocknet-data-mainnet/checkpoints.dat
```

Существующий файл будет заменён — так обновляется старая копия.

### 3. Проверьте SHA-256

Страница публикует SHA-256 текущего файла. Вычислите хеш своей копии и сравните:

```sh
sha256sum blocknet-data-mainnet/checkpoints.dat
```

В macOS используйте `shasum -a 256`. Хеш меняется при каждом добавлении точки, поэтому сравнивайте сразу после загрузки.

### 4. Выборочно сверьте точку в обозревателе

Любую строку можно проверить в [обозревателе Blocknet](https://explorer.blocknetcrypto.com). Откройте высоту из файла, например `explorer.blocknetcrypto.com/block/68900`, и сравните хеш со строкой 68 900. Мы проверили последнюю точку 25 октября 2026 года: хеши совпали.

### 5. Запустите ноду

Запустите или перезапустите демон. При старте он читает `checkpoints.dat` и быстро синхронизируется до последней точки. В интерактивной оболочке core (`--cli`) команда `load-checkpoints` загружает файл в уже работающую ноду и сообщает целевую высоту:

```text
> load-checkpoints
```

Точки полезны отстающей ноде. Если цепь уже выше последней точки, нода проверяет каждый блок полностью, и новый файл ничего не меняет.

## Как проверить файл скриптом?

Пул публикует сведения в JSON без API-ключа по адресу `https://bntpool.com/api/checkpoints`:

| Поле | Значение |
|---|---|
| `available` | Доступен ли файл |
| `url` | Адрес загрузки |
| `entries` | Количество точек |
| `latest_height`, `latest_hash` | Последняя точка и хеш её блока |
| `bytes`, `sha256` | Размер и SHA-256 |
| `updated_at` | Последнее изменение как Unix-время |

Загрузка содержит заголовки `X-Checkpoint-Height`, `X-Checkpoint-Sha256` и `ETag` из хеша. Скрипт может отправить `If-None-Match` и быстро получить `304 Not Modified`, если изменений нет:

```sh
curl -s https://bntpool.com/api/checkpoints | jq '{latest_height, sha256}'
```

Ответы могут кешироваться 60 секунд: этого достаточно для файла, обновляемого примерно раз в восемь часов.

<Note>
По информации blocknetcrypto.com, планируемое обновление Faraday принесёт более лёгкое доказательство работы для ускорения новых нод. Пока контрольные точки — быстрый способ догнать цепь.
</Note>
