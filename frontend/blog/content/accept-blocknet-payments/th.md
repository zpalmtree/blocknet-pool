รับชำระด้วย Blocknet โดยแจ้งยอด BNT ให้ชัดเจน ตรวจสอบเงินเข้าในกระเป๋าของคุณ และเก็บหลักฐานไว้กับคำสั่งซื้อ ตัวอย่างสมมตินี้ใช้ **1.25 BNT** กับเลขอ้างอิง **order-1042** อ้างอิงกระเป๋าเดสก์ท็อปรุ่นเผยแพร่ v0.22.0 และภาพหน้าจอที่ระบุชัดว่าเป็นข้อมูลสาธิต

## รับชำระด้วย Blocknet อย่างไร

<Answer>
ตกลงยอด BNT และเลขอ้างอิง ส่งคำขอไปยังที่อยู่ที่คุณควบคุม แล้วรอเงินเข้าในกระเป๋าที่ซิงก์แล้ว เทียบยอดและเลขอ้างอิง ตรวจสอบการยืนยัน บันทึก ID ธุรกรรม และเปลี่ยนสถานะเป็นชำระแล้วตามนโยบายการยืนยันที่ตกลงกับลูกค้า
</Answer>

ใช้[คู่มือกระเป๋าเดสก์ท็อป](https://seineminer.com/th/blog/blocknet-desktop-wallet/) หากต้องสร้างหรือเปิดกระเป๋า เก็บข้อมูลสำรองสำหรับกู้คืนแยกจากข้อมูลคำสั่งซื้อ การรับเงินจากลูกค้าไม่จำเป็นต้องเปิดโปรแกรมขุดหรือเข้าร่วมพูล

## กำหนดยอดและระบุคำสั่งซื้อ

บันทึกเลขอ้างอิง จำนวน BNT ที่อยู่รับเงิน และสิ่งที่ลูกค้าซื้อ หากเสนอราคาเป็นสกุลเงินอื่น ให้ตกลงยอด BNT และระยะเวลาที่ราคานั้นใช้ได้ก่อนชำระ ลิงก์ระบุยอดที่ขอ แต่ไม่ได้ปรับอัตราแลกเปลี่ยนหรือบังคับเวลาหมดอายุ

ตัวอย่างขอ **1.25 BNT** และใช้ **order-1042** เป็นข้อความ ใช้เพียงเลขคำสั่งซื้อก็พอ เก็บที่อยู่จัดส่งและข้อมูลลูกค้าอื่นไว้ในระบบส่วนตัว [ข้อความที่เข้ารหัส](https://seineminer.com/th/blog/blocknet-encrypted-memos/) จะไปกับการชำระเงิน แต่ใครก็ตามที่ได้รับลิงก์ร่วมกันสามารถอ่านข้อความในลิงก์ได้

ที่ **Receive → Payment Request** กรอกยอดและข้อความ แล้วเลือก **Generate Payment Link** ตรวจสอบผู้รับและยอดก่อนส่ง [คู่มือลิงก์ชำระเงิน](https://seineminer.com/th/blog/blocknet-payment-links/) อธิบายรูปแบบและผู้รับแบบชื่อ สำหรับใบแจ้งหนี้ที่กำหนดไว้ ให้เก็บที่อยู่เต็มไว้กับคำขอ

## ตรวจสอบเงินเข้าในกระเป๋าของคุณ

ขอให้ลูกค้าใส่เลขอ้างอิงและเก็บ ID ธุรกรรมไว้ เมื่อโหนดและกระเป๋าซิงก์ทันแล้ว เปิด **History** หาเงินเข้าและเทียบยอดกับข้อความ ผู้จ่ายเปลี่ยนได้ทั้งสองช่อง คำขอจึงไม่ใช่หลักฐานว่าส่งเท่าไรจริง

เก็บ ID แบบเต็มและยอดที่ได้รับ อย่านับซ้ำเพราะธุรกรรมเดียวกันปรากฏทั้ง Dashboard และ History หรือเพราะลูกค้าส่ง ID เดิมมาอีก จับคู่เงินเข้าเป็นรายการ ไม่ใช้การเปลี่ยนแปลงของยอดรวม ซึ่งอาจรวมเงินจากพูล ลูกค้ารายอื่น หรือการโอนของคุณเอง

หากไม่พบเงินเข้า ให้เทียบที่อยู่ปลายทางเต็มและ ID กับลูกค้า แล้วตรวจสอบการซิงก์ ภาพหน้าจอการส่งให้ข้อมูลประกอบ แต่กระเป๋าฝั่งรับของคุณเป็นตัวระบุยอดที่ได้รับ

## เมื่อใดควรเปลี่ยนสถานะเป็นชำระแล้ว

แยกระหว่างเงินเข้าที่ยังไม่ยืนยัน ธุรกรรมที่อยู่ในบล็อก และเงินที่ใช้จ่ายได้ กระเป๋ารุ่นเผยแพร่จะรออีกสิบบล็อกหลังบล็อกที่บรรจุการชำระเงินทั่วไป ก่อนให้ใช้เอาต์พุตนั้น [คู่มือระยะเวลาโอน](https://seineminer.com/th/blog/blocknet-transfer-time/) อธิบายตัวนับและเวลารอที่ไม่แน่นอน

แจ้งนโยบายการยืนยันก่อนชำระ ขั้นตอนแบบทำเองที่เรียบง่ายคือรอให้เงินเข้าที่ตรงกันใช้จ่ายได้ก่อนส่งสินค้า แค่เห็นยอดเงินเข้ายังไม่ครบขั้นตอน อย่ารับประกันเวลาส่งมอบจากตัวนับของกระเป๋า เพราะบล็อกมาถึงในช่วงเวลาที่ต่างกัน อ่าน[การขุดช่วยรักษาความปลอดภัยให้การชำระเงินอย่างไร](/blog/th/how-mining-secures-blocknet-payments/) เพื่อเข้าใจความลึกของการยืนยัน

## จัดการจ่ายไม่ครบ จ่ายเกิน หรือจับคู่ไม่ได้

| สิ่งที่ตรวจสอบแล้ว | ขั้นตอนถัดไป |
|---|---|
| 1.00 BNT สำหรับคำสั่งซื้อ 1.25 BNT | บันทึกว่าชำระบางส่วนและขออีก 0.25 BNT |
| เงินเข้าเพิ่มภายหลัง 0.25 BNT | เก็บ ID ทั้งสอง รวมยอด 1.25 BNT เพียงครั้งเดียว และตรวจสอบการยืนยันทั้งคู่ |
| มากกว่า 1.25 BNT | ตกลงคืนเงินหรือให้เครดิตและบันทึกข้อตกลง |
| ยอดถูกต้องแต่ไม่มีข้อความ | เทียบ ID แบบเต็มและปลายทางกับลูกค้าก่อนจับคู่ |
| การชำระเงินยังรอดำเนินการ | คงสถานะรอยืนยันและตรวจสอบอีกครั้ง |

เมื่อต้องคืนเงิน ให้ลูกค้ายืนยันที่อยู่รับเงินผ่านบทสนทนาเดิมของคำสั่งซื้อ อย่าอนุมานที่อยู่คืนเงินจากธุรกรรมสาธารณะ อินพุตของ Blocknet ไม่ได้ให้ที่อยู่ผู้ส่งแบบทั่วไป ตรวจสอบยอด ปลายทาง และค่าธรรมเนียมก่อนยืนยันการส่งใหม่ แล้วเก็บ ID ไว้กับรายการเดิม

## แชร์เฉพาะหลักฐานที่จำเป็น

ตัวสำรวจช่วยตรวจสอบการรวมธุรกรรมในบล็อก แต่ไม่เปิดเผยยอดส่วนตัวที่ที่อยู่คุณได้รับ หากมีข้อโต้แย้ง ผู้ส่งให้หลักฐานเฉพาะธุรกรรมได้ตาม[คู่มือหลักฐานการชำระเงิน](https://seineminer.com/th/blog/blocknet-payment-proof/) ตรวจสอบผู้รับที่ตรงกัน ยอด และสถานะบนเชน ความถูกต้องของคีย์เพียงอย่างเดียวไม่พอ

เก็บคำสั่งซื้อ คำขอ ID เงินเข้า ยอดที่ตรวจสอบแล้ว การตัดสินใจเรื่องการยืนยัน และรายการคืนเงินไว้ด้วยกันเป็นส่วนตัว แชร์เฉพาะใบรับหรือหลักฐานที่เกี่ยวข้อง อย่าส่งคำกู้คืน รหัสผ่านกระเป๋า หรือคีย์ดูข้อมูลส่วนตัวทั้งกระเป๋าเป็นหลักฐาน

หากขุด BNT ด้วย ให้แยก[บันทึกเงินจ่ายจากพูล](/blog/th/track-your-miner-on-bntpool/) จากคำสั่งซื้อ แม้ใช้กระเป๋าเดียวกัน เพื่อรู้ว่าธุรกรรมใดจ่ายใบแจ้งหนี้ใด
