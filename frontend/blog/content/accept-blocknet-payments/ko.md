Blocknet 대금을 받으려면 BNT 금액을 명확히 안내하고, 본인 지갑에서 입금을 확인한 뒤 주문에 기록하세요. 이 예시는 **1.25 BNT**, 주문 번호 **order-1042**를 사용합니다. 배포된 데스크톱 지갑 v0.22.0을 기준으로 하며 스크린샷에는 데모라고 명시한 데이터를 사용합니다.

## Blocknet 결제를 어떻게 받나요?

<Answer>
BNT 금액과 주문 번호에 합의하고 본인이 관리하는 주소로 결제 요청을 보냅니다. 동기화된 지갑에서 입금을 기다린 뒤 금액과 번호를 대조하고 확인 상태를 살펴보세요. 거래 ID를 기록하고 고객과 합의한 확인 정책에 따라 주문을 결제 완료로 처리합니다.
</Answer>

지갑 생성이나 열기는 [데스크톱 지갑 안내](https://seineminer.com/ko/blog/blocknet-desktop-wallet/)를 참고하세요. 복구용 백업은 주문 기록과 별도로 보관합니다. 고객의 결제를 받는 데 채굴기 실행이나 풀 가입은 필요하지 않습니다.

## 금액을 정하고 주문을 식별하세요

주문 번호, BNT 금액, 수령 주소, 구매 내용을 기록합니다. 다른 통화로 견적을 냈다면 결제 전에 BNT 금액과 견적 유효 기간에 합의하세요. 결제 링크는 요청 금액을 담지만 환율을 갱신하거나 만료 시점을 강제하지 않습니다.

예시는 **1.25 BNT**를 요청하고 메모로 **order-1042**를 사용합니다. 주문 번호면 충분합니다. 배송 주소와 다른 고객 정보는 비공개 시스템에 보관하세요. [암호화된 메모](https://seineminer.com/ko/blog/blocknet-encrypted-memos/)는 결제와 함께 전달되지만 공유 링크에 적힌 메모는 링크를 받은 누구나 읽을 수 있습니다.

**Receive → Payment Request**에서 금액과 메모를 입력하고 **Generate Payment Link**를 선택합니다. 공유 전에 수령인과 금액을 확인하세요. [결제 링크 안내](https://seineminer.com/ko/blog/blocknet-payment-links/)는 링크 형식과 이름 기반 수령인을 설명합니다. 개별 청구서에는 전체 수령 주소도 저장하세요.

## 본인 지갑에서 입금을 확인하세요

고객에게 주문 번호를 포함하고 거래 ID를 보관하도록 요청합니다. 노드와 지갑의 동기화가 끝나면 **History**에서 입금을 찾으세요. 금액과 메모를 주문과 대조합니다. 결제자는 둘 다 바꿀 수 있으므로 요청 자체는 실제 송금 내용을 입증하지 않습니다.

전체 거래 ID와 받은 금액을 저장하세요. Dashboard와 History에 함께 표시되거나 고객이 같은 ID를 다시 보냈다고 두 번 계산하지 마세요. 전체 잔액의 변화 대신 개별 입금을 대조합니다. 잔액에는 채굴 보상, 다른 고객의 결제, 본인의 이체도 포함될 수 있습니다.

입금이 보이지 않으면 고객과 전체 목적지 주소 및 거래 ID를 대조하고 동기화를 확인합니다. 송금 화면은 참고 자료가 되지만 수령 금액은 본인의 수령 지갑에서 확인해야 합니다.

## 언제 결제 완료로 처리하나요?

미확인 입금, 블록에 포함된 거래, 사용할 수 있는 자금을 구분하세요. 배포된 지갑은 일반 결제가 담긴 블록 이후 열 개의 블록을 더 기다린 뒤 해당 출력을 사용할 수 있게 합니다. [전송 시간 안내](https://seineminer.com/ko/blog/blocknet-transfer-time/)는 카운터와 변동하는 대기 시간을 설명합니다.

결제 전에 확인 정책을 안내합니다. 간단한 수동 절차는 일치하는 입금이 사용 가능해질 때까지 기다린 뒤 상품이나 서비스를 제공합니다. 입금액이 보인다는 사실만으로 확인이 끝난 것은 아닙니다. 블록 간격이 달라지므로 지갑의 카운트다운으로 고정된 제공 시각을 약속하지 마세요. [채굴이 결제를 보호하는 방식](/blog/ko/how-mining-secures-blocknet-payments/)은 확인 깊이의 의미를 설명합니다.

## 부족·초과·미확인 주문의 결제를 처리하세요

| 확인한 내용 | 다음 조치 |
|---|---|
| 1.25 BNT 주문에 1.00 BNT 입금 | 일부 결제로 기록하고 남은 0.25 BNT를 요청합니다. |
| 이후 0.25 BNT 추가 입금 | 두 ID를 저장하고 합계 1.25 BNT를 한 번만 계산하며 두 입금의 확인 상태를 점검합니다. |
| 1.25 BNT 초과 | 환불 또는 합의한 크레딧 여부를 확인하고 결정을 기록합니다. |
| 금액은 맞지만 메모 없음 | 주문에 배정하기 전에 고객과 전체 ID와 목적지를 확인합니다. |
| 대기 중인 결제 | 확인 대기 상태로 두고 현재 상태를 다시 확인합니다. |

환불할 때는 기존 주문 대화에서 고객에게 수령 주소를 확인하세요. 공개 거래에서 반환 주소를 추정하지 마세요. Blocknet의 공개 입력은 일반적인 발신자 주소를 제공하지 않습니다. 새 송금을 승인하기 전에 환불액, 목적지, 수수료를 검토하고 거래 ID를 원래 결제와 함께 보관합니다.

## 필요한 결제 증거만 공유하세요

공개 탐색기는 거래 포함 여부 확인을 돕지만 주소가 받은 비공개 금액은 공개하지 않습니다. 수령에 이견이 있다면 송신자가 [결제 증명 안내](https://seineminer.com/ko/blog/blocknet-payment-proof/)에 따라 거래별 증거를 제공할 수 있습니다. 수령인 일치, 금액, 체인 상태를 검증하세요. 키가 유효하다는 사실만으로는 충분하지 않습니다.

주문, 요청, 입금 ID, 검증한 금액, 확인 관련 판단, 환불을 비공개 기록으로 함께 보관합니다. 관련 영수증이나 증명만 공유하세요. 복구 단어, 지갑 비밀번호, 지갑 전체의 비공개 보기 키를 결제 증거로 보내지 마세요.

BNT 채굴도 한다면 같은 지갑을 쓰더라도 [풀 지급 기록](/blog/ko/track-your-miner-on-bntpool/)을 고객 주문과 구분하세요. 어떤 이체가 어떤 청구서를 결제했는지 명확해집니다.
