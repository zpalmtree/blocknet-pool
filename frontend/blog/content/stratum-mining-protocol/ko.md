bntpool.com에서 seine로 오는 작업과 풀로 돌아가는 셰어를 따라가 보세요. 흐름을 이해하면 연결 메시지, 작업 업데이트, 제출 응답을 읽기 쉬워집니다. 이 가이드는 bntpool.com 구현을 설명합니다. 초기 주소와 지급 주소 설정은 [풀 설정 가이드](/blog/ko/mine-blocknet-on-bntpool/)를 참고하세요.

## 채굴에서 Stratum이란 무엇인가요?

<Answer>
Stratum은 채굴기가 풀의 작업을 받고 결과를 제출하는 통신 계층입니다. seine와 bntpool.com에서는 지속적인 TCP 연결이 로그인, 작업, 셰어의 JSON 메시지를 전달합니다. 해시는 내 컴퓨터에서 계산하고 풀은 노드에서 블록 템플릿을 받아 제출 작업을 처리합니다.
</Answer>

*채굴기는 로그인과 셰어를 보내고 작업과 응답을 받으며, 풀은 노드와 템플릿 및 블록 후보를 교환합니다.*

## 엔드포인트는 채굴 연결을 지정합니다

문서화된 주소는 `stratum+tcp://bntpool.com:3333`입니다. 스킴은 전송 방식, 호스트 이름은 서비스, 포트는 채굴 리스너를 지정합니다. 브라우저의 `https://bntpool.com` 연결은 용도가 다릅니다. [Get Started](/start)에서 전체 채굴 주소를 복사해 풀 설정에 넣어 의도한 연결을 여세요.

지속 연결을 통해 양쪽은 작업이 준비될 때 메시지를 보낼 수 있습니다. bntpool은 줄바꿈으로 구분된 JSON과 요청·응답을 연결하는 요청 ID를 사용합니다. 이는 이 풀의 통신 형식입니다. 채굴기는 Blocknet 해시 알고리즘뿐 아니라 형식과 기능도 지원해야 합니다. 현재 필드는 [프로토콜 소스](https://github.com/zpalmtree/blocknet-pool/blob/6521e7c6991629cf1bf364b5b5afea597b6999e0/crates/pool-common/src/protocol.rs)에 있습니다.

## 채굴기 로그인 때 무엇이 일어나나요?

클라이언트는 지급 주소, 장비 이름, 프로토콜 버전, 지원 기능을 담은 `login` 요청을 보냅니다. 풀은 확인 후 프로토콜 정보와 필수 기능을 돌려줍니다. 이로써 세션의 작업 교환 방식을 정합니다. TCP 연결 성공이 첫 단계이고 로그인 승인은 애플리케이션 대화도 시작됐음을 뜻합니다.

장비 이름은 같은 주소 아래 한 컴퓨터의 활동을 구분합니다. 여러 장비에는 다른 이름을 쓰고 의도한 지급 주소를 유지하세요. 로그인에는 수신 주소가 필요하며 지갑 복구 구문이나 개인 지출 키는 필요하지 않습니다. 세션이 승인되고 작업이 있으면 풀은 `job` 메시지를 보내 해싱을 시작하게 합니다.

## 채굴 작업에는 어떤 정보가 있나요?

할당 및 기반 템플릿 식별자, 헤더 데이터, 블록 높이, 셰어 목표, 네트워크 목표, 할당 nonce 범위를 포함합니다. nonce는 해시를 계산하며 바꿔 시도하는 값입니다. 범위는 세션의 탐색 공간을 정합니다. 작업 ID는 나중의 제출을 처음 할당한 작업 및 조건과 연결합니다.

셰어 목표는 작업 증거로 제출할 결과를 정하고, 네트워크 목표는 블록 후보가 될 결과를 정합니다. 대부분의 적격 셰어는 블록이 되지 않고 풀 회계에 쓰입니다. [난이도 가이드](/blog/ko/mining-difficulty-explained/)는 목표 크기와 기대 작업량의 관계를 설명합니다. 프로토콜은 목표를 할당의 일부로 전달합니다.

## 연결을 유지한 채 작업이 바뀔 수 있습니다

새 작업 자체가 연결 끊김을 뜻하지는 않습니다. 풀은 상위 템플릿 변경에 따라 갱신하거나 셰어 난이도를 바꾼 새 할당을 보낼 수 있습니다. 가변 난이도는 관측한 작업 흐름에 맞춰 제출 기준을 조정합니다. 채굴기는 새 할당을 따르고 지속 연결은 양방향 메시지를 계속 전달합니다.

기술 로그의 작업 ID와 템플릿 ID를 구분하세요. 여러 할당이 서로 다른 세션 정보를 가지면서 같은 템플릿을 가리킬 수 있습니다. 높이만으로 모든 작업 변화를 설명할 수는 없습니다. 일반 운영에서는 작업 수신, 해싱 진행, 제출 응답을 확인하면 됩니다. 결과 활동을 보는 곳은 [추적 가이드](/blog/ko/track-your-miner-on-bntpool/)에 있습니다.

## 셰어 제출에는 무엇이 들어가나요?

적격 결과를 찾으면 seine는 작업, nonce, 신고 해시를 지정한 `submit`을 보냅니다. 풀은 할당 맥락으로 처리하고 요청 ID에 연결된 응답을 반환합니다. 신고 해시는 메시지의 일부이며 이후 처리는 풀의 검증과 블록 검증 경로가 결정합니다. 블록 후보는 검증을 위해 daemon에 제출합니다.

응답은 승인 여부, 검증 상태, 난이도 정보를 보고할 수 있습니다. 성공 응답을 모두 블록 발견으로 보지 말고 필드를 별도로 읽으세요. 풀 회계와 지급은 이 교환 이후에 이뤄집니다. [셰어 결과 가이드](/blog/ko/accepted-rejected-stale-shares/)는 제출 결과를, [PPLNS 가이드](/blog/ko/how-pplns-payouts-work/)는 적격 작업과 보상·지급의 관계를 설명합니다.

## 이 순서로 채굴기를 어떻게 점검하나요?

엔드포인트 도달, 로그인 승인, 작업 수신, 해싱 활성, 제출 응답 순으로 읽으세요. 연결이 끊기면 클라이언트는 재연결해 세션을 만든 후 새 작업을 받습니다. 정확한 로그 문구와 시각으로 관련 단계를 찾으세요. 풀 웹페이지가 동작해도 그 컴퓨터에서 채굴 포트에 접근할 수 있다는 증거는 아닙니다.

의도한 지급 주소로 [My Stats](/stats)를 열고 [풀 상태](/status)에서 서비스 상황을 확인하세요. 시작이나 재연결 후 셰어 기반 해시레이트가 관측을 모을 시간을 주세요. 통신과 지급 시기는 구분해야 합니다. 로그인은 세션을 준비하고 작업은 할 일을 주며 셰어는 결과를 보고하고 이후 보상 단계는 풀 회계가 결정합니다.
