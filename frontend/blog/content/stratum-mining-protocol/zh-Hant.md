跟隨一份工作從 bntpool.com 到 seine，再看份額如何回到礦池。理解這段對話，有助於讀懂連線訊息、工作更新及提交回應。本指南說明 bntpool.com 的實作；首次設定端點與收款位址，請看[礦池設定指南](/blog/zh-hant/mine-blocknet-on-bntpool/)。

## 挖礦中的 Stratum 是什麼？

<Answer>
Stratum 是礦工接收礦池工作並提交結果的通訊層。seine 與 bntpool.com 使用持續 TCP 連線傳送登入、工作和份額的 JSON 訊息。你的機器在本機計算雜湊，礦池則從節點取得區塊範本並處理提交的工作。
</Answer>

*礦工傳送登入及份額，接收工作與回應；礦池和節點交換範本及候選區塊。*

## 端點指定挖礦連線

文件中的端點是 `stratum+tcp://bntpool.com:3333`。協定方案告知程式採用哪種傳輸，主機名稱識別服務，連接埠選擇挖礦接聽器。瀏覽器的 `https://bntpool.com` 連線用途不同。從 [Get Started](/start) 複製完整挖礦端點至礦池設定，讓用戶端開啟預期連線。

持續連線讓雙方在有工作時傳送訊息。bntpool 使用換行分隔的 JSON，並以要求 ID 對應要求與回應。這是該礦池的通訊格式；礦工除了支援 Blocknet 雜湊演算法，也必須支援格式及能力。[協定原始碼](https://github.com/zpalmtree/blocknet-pool/blob/6521e7c6991629cf1bf364b5b5afea597b6999e0/crates/pool-common/src/protocol.rs)記錄目前欄位。

## 礦工登入時會發生什麼？

用戶端傳送 `login` 要求，包含收款位址、礦機名稱、協定版本及支援能力。礦池檢查後回傳協定資訊與必要能力，藉此確立工作階段交換工作的方式。TCP 連線成功是第一步；登入獲接受表示應用層對話也已開始。

礦機名稱用來區分同一位址下各台機器的活動。多機請使用不同名稱，並維持預期收款位址。登入需要接收位址，不需要錢包復原詞組或私密支出金鑰。工作階段獲准且有工作時，礦池傳送 `job` 訊息，讓礦工開始計算。

## 挖礦工作包含哪些資訊？

工作包含指派與底層範本的識別碼、標頭資料、區塊高度、份額目標、網路目標及分配的 nonce 範圍。nonce 是雜湊嘗試中持續改變的值，範圍定義此工作階段的搜尋空間。工作 ID 讓礦池將後續提交對應至最初指派的工作與條件。

份額目標決定哪些結果應作為工作證據提交；網路目標決定哪些可成為候選區塊。多數合格份額用於礦池帳務，不會成為區塊。[難度指南](/blog/zh-hant/mining-difficulty-explained/)說明目標大小與預期工作量的關係；協定將這些目標作為工作的一部分交給礦工。

## 連線保持時，工作也能改變

新工作本身不代表礦工斷線。上游範本改變時，礦池可以更新工作，也能下發含新份額難度的指派。可變難度系統依觀察到的工作流調整提交門檻。礦工遵循新指派，而持續連線繼續雙向傳遞訊息。

閱讀技術紀錄時請區分工作 ID 與範本 ID。多個指派可參照同一範本，但帶有不同工作階段細節。高度本身無法描述每項變化。一般操作只需確認工作抵達、雜湊計算前進、提交收到回應；[追蹤指南](/blog/zh-hant/track-your-miner-on-bntpool/)說明活動的查看位置。

## 份額提交包含什麼？

找到合格結果後，seine 傳送 `submit`，指定工作、nonce 與宣告的雜湊。礦池利用指派脈絡處理，回傳對應要求 ID 的回應。宣告值是訊息的一部分，後續處理由礦池驗證與區塊驗證流程決定。候選區塊會提交給 daemon 驗證。

回應可能報告接受狀態、驗證狀態與難度資訊。請將它們視為獨立欄位，不要把每次成功回應都當作發現區塊。礦池記帳與支付在這段訊息交換之外進行。[份額結果指南](/blog/zh-hant/accepted-rejected-stale-shares/)說明提交結果，[PPLNS 指南](/blog/zh-hant/how-pplns-payouts-work/)說明合格工作與獎勵、支付的關係。

## 如何依這個順序檢查礦工？

依序查看：抵達端點、登入獲准、收到工作、雜湊運作、提交獲回應。連線中斷後，用戶端重新連線並建立工作階段，再接收更多工作。使用準確紀錄與時間戳記定位相關階段。礦池網頁正常可提供參考，但不能證明該機器能存取挖礦連接埠。

為預期收款位址開啟 [My Stats](/stats)，並查看[礦池狀態](/status)了解服務情況。啟動或重連後，讓以份額估計的雜湊率有時間累積樣本。通訊與付款時間要分開：登入準備工作階段，工作提供任務，份額報告結果，之後的獎勵階段由礦池帳務決定。
