Проследите задание от bntpool.com к seine и шару обратно к пулу. Понимание диалога помогает читать сообщения соединения, обновления заданий и ответы. Здесь описана реализация bntpool.com; начальные адрес сервера и адрес выплат задаются по [руководству пула](/blog/ru/mine-blocknet-on-bntpool/).

## Что такое Stratum в майнинге?

<Answer>
Stratum — слой связи, через который майнер получает работу пула и отправляет результаты. В seine и bntpool.com постоянное TCP-соединение передаёт JSON-сообщения входа, заданий и шар. Компьютер вычисляет хеши локально; пул получает шаблоны блоков от узла и обрабатывает отправленную работу.
</Answer>

*Майнер отправляет вход и шары, получает задания и ответы, а пул обменивается с узлом шаблонами и кандидатами в блоки.*

## Конечная точка определяет соединение майнинга

Документированный адрес — `stratum+tcp://bntpool.com:3333`. Схема указывает транспорт, имя хоста — сервис, порт — слушатель майнинга. Соединение браузера с `https://bntpool.com` имеет другую цель. Скопируйте полный адрес из [Get Started](/start) в настройку пула, чтобы открыть нужное соединение.

Постоянное соединение позволяет обеим сторонам посылать сообщения по мере появления работы. bntpool использует JSON с разделением строками и ID запросов, связывающие ответы. Это формат данного пула: майнер должен поддерживать его, возможности протокола и алгоритм Blocknet. [Исходник протокола](https://github.com/zpalmtree/blocknet-pool/blob/6521e7c6991629cf1bf364b5b5afea597b6999e0/crates/pool-common/src/protocol.rs) фиксирует текущие поля.

## Что происходит при входе майнера?

Клиент отправляет `login` с адресом выплат, именем рига, версией протокола и поддерживаемыми возможностями. Пул проверяет вход и возвращает сведения протокола и обязательные возможности. Так определяется обмен работой. TCP-соединение — первый шаг; принятый вход подтверждает начало диалога приложения.

Имя рига отличает машину в рамках адреса. Для нескольких ригов используйте разные имена и нужный адрес выплат. Для входа нужен адрес получения, а не фраза восстановления или приватный ключ расходования. После принятия сессии при доступной работе пул отправляет `job`, позволяя начать хеширование.

## Какие данные содержит задание?

Задание содержит ID назначения и шаблона, данные заголовка, высоту, цели шары и сети, а также диапазон nonce. Nonce — изменяемое при хешировании значение. Диапазон задаёт пространство поиска сессии. ID задания связывает последующую отправку с исходной работой и условиями.

Цель шары определяет результаты для отправки как доказательство работы. Цель сети определяет возможные кандидаты в блоки. Большинство шар участвует в учёте, не становясь блоками. [Руководство по сложности](/blog/ru/mining-difficulty-explained/) объясняет размер цели и ожидаемую работу; протокол передаёт цели в назначении.

## Задания меняются при открытом соединении

Новое задание само по себе не означает разрыв. Пул может обновить работу при изменении шаблона узла или выдать назначение с новой сложностью шар. Переменная сложность адаптирует порог отправки к наблюдаемой работе. Майнер следует новому назначению, пока соединение продолжает передавать сообщения в обе стороны.

Различайте ID заданий и шаблонов в технических журналах. Несколько назначений могут использовать один шаблон с разными параметрами сессии. Высота не описывает все изменения. Оператору полезно проверять поступление заданий, ход хеширования и ответы; [руководство по отслеживанию](/blog/ru/track-your-miner-on-bntpool/) показывает соответствующую активность.

## Что содержит отправка шары?

Найдя подходящий результат, seine отправляет `submit` с заданием, nonce и заявленным хешем. Пул обрабатывает контекст назначения и отвечает с ID запроса. Заявленный хеш — часть сообщения; проверка и валидация блока определяют продолжение. Кандидат в блок отправляется демону для проверки.

Ответ может содержать принятие, статус проверки и сложность. Читайте поля отдельно, не считая каждый успешный ответ найденным блоком. Учёт и выплаты происходят за пределами этого обмена. [Руководство по шарам](/blog/ru/accepted-rejected-stale-shares/) объясняет результаты, а [руководство PPLNS](/blog/ru/how-pplns-payouts-work/) связывает подходящую работу с наградами и выплатами.

## Как использовать последовательность для проверки майнера?

Читайте этапы по порядку: сервер доступен, вход принят, задание получено, хеширование активно, отправки отвечены. При разрыве клиент переподключается и создаёт сессию перед новой работой. Точное сообщение и время помогают найти этап. Работающий сайт не доказывает доступность порта майнинга с этой машины.

Откройте [My Stats](/stats) для нужного адреса и [статус пула](/status) для состояния сервисов. После запуска или переподключения дайте оценкам хешрейта накопить шары. Разделяйте протокол и сроки выплаты: вход готовит сессию, задания дают работу, шары сообщают результаты, а учёт определяет следующие стадии награды.
