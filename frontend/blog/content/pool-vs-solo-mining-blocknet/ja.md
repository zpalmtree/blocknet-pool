このガイドはbntpool.comで採掘するか、自分のノードでソロ採掘するかを判断するためのものです。自分の速度で単独発見できるブロック数、プールによる継続的な支払いへの分割、seineでの両方式の設定を説明します。

## Blocknetはプールとソロのどちらで採掘すべきですか？

<Answer>
計算の原則は同じで、ネットワークのハッシュレートに占める割合がブロックの取り分を決めます。bntpool.comではプールが見つけるすべてのブロックから受け取るため、発見に合わせて継続的に支払われます。ソロでは自分が見つけたブロックの全額を保持し、自分のノードを運用する大規模構成に合います。
</Answer>

多くのマイナーにはbntpool.comが簡単な出発点です。seineの標準プールなのでアドレス以外の設定がなく、ノードの運用や同期も不要です。ソロも完全対応しており、daemonモードで自分のBlocknetノードへ直接接続できます。以下でハードウェアに合う方を判断します。

## ソロなら何ブロック見つかりますか？

<Answer>
Blocknetは5分に1ブロック、1日288ブロックを目指します。単独採掘の期待値は1日288 ×（自分の速度 ÷ ネットワークの速度）です。1日をその数で割ると自分のブロック間の平均時間になります。現在のネットワーク速度はbntpool.comのダッシュボードで確認できます。
</Answer>

ネットワーク全体が平均300秒ごとに発見するよう難易度を調整するため、この式が成り立ちます。難易度は成功までに期待されるハッシュ数に相当します。各ハッシュの確率は等しく、自分が担当するネットワークのハッシュ割合が発見ブロックの期待割合です。

必要な値は二つです。

- **自分のハッシュレート。** 採掘中のseineダッシュボード、プール利用後は[統計ページ](/stats)に表示されます。
- **ネットワークのハッシュレート。** [bntpool.comのダッシュボード](/)のNetwork Hashrateにあり、Pool Hashrateの隣です。どちらも変動するため計算時に確認します。

発見した各ブロックはその月の報酬を払います。[ブロック報酬表](/blog/ja/blocknet-block-reward-schedule/)に月別の値があります。

## 計算例

<Note>
以下は計算用の仮の丸い数字で、現在値ではありません。自分の見積もりにはダッシュボードの最新ネットワーク速度を使ってください。
</Note>

ネットワークを50,000 H/sとします。50 H/sのリグはseineがAMD EPYC Zen 5サーバー一台で測った値に近く、ネットワークの0.1%です。このリグと二つの大規模構成がソロで得る期待値は次のとおりです。

| 自分の速度の例 | ネットワーク割合 | 1日の期待ブロック数 | 平均発見間隔 |
|---|---|---|---|
| 50 H/s | 0.1% | 0.288 | 約83時間（3.5日） |
| 500 H/s | 1% | 2.88 | 約8.3時間 |
| 5,000 H/s | 10% | 28.8 | 約50分 |

50 H/sのリグを合計5,000 H/sのプールへ入れると、プールは1日約28.8ブロック、平均50分に一件を見つけます。リグの仕事割合は1%なので、各ブロックの1%を受け取ります。計上される仕事は同じ1日0.288ブロック分です。違いは受け取り方で、ソロの数日ごとの全額に対し、約50分ごとの小さな取り分になります。

表は大規模構成にソロが合う理由も示します。5,000 H/sなら同じ規模のプールと同頻度で発見でき、自分だけでも継続的な収益になります。

実際のプールデータに日付を付けた例でBNTへ換算するには、[Blocknetの採掘報酬を見積もる方法](/blog/ja/estimate-blocknet-mining-rewards/)をご覧ください。

## なぜプールの支払いはより定期的なのですか？

bntpool.comは全参加者のハッシュレートを合計するため、一台よりずっと頻繁にブロックを見つけます。PPLNSで、発見前6時間の各マイナーのシェア難易度に比例して報酬を分配します。

実用上の効果は次のとおりです。

- **すべての発見から報酬。** シェアが6時間のウィンドウ内にある限り各ブロックの取り分が入り、[ブロックページ](/blocks)で追えます。
- **自動支払い。** 60ブロックの深さで取り分が承認済み残高に入り、0.1 BNTに達すると送金されます。記録は[支払いページ](/payouts)にあります。
- **再起動後も継続。** 送信済みシェアは6時間残るため、再起動やドライバー更新で位置は消えません。
- **マイナーだけでよい。** ノード、テンプレート作成、ブロック送信はプールが担当します。複数リグから一つのアドレスやBlocknet IDの`@name`へ採掘できます。

[PPLNSの支払いガイド](/blog/ja/how-pplns-payouts-work/)に分配の手順と計算例があり、[Get Started](/start)に現在の設定値があります。

## なぜBlocknetをソロで採掘するのですか？

ソロは全工程を自分で管理できます。自分のノードがテンプレートを作り各ブロックを検証し、発見した全報酬がノードのウォレットへ直接入ります。

頻繁に発見できる速度がある場合に特に合います。上の例の10%の構成なら約50分ごとで、プールと同じくらい定期的です。ウォレットや他のサービスのためにすでにノードを動かしているなら、その上にマイナーを加えればよいのです。

seineはこのモードにも対応しています。ノードのテンプレートを使い、再起動などでノードがテンプレートを忘れた場合には、解決済みブロック全体を再送してチェーンへ届けます。

## seineでソロを設定するには？

1. **ノードを導入して同期。** `blocknet`ラッパーで次を実行します。

   ```sh
   blocknet install latest
   blocknet start mainnet
   ```

   API cookieは`~/.config/bnt/data/mainnet/api.cookie`に保存されます。初回同期を速める`checkpoints.dat`をbntpool.comの[チェックポイントページ](/checkpoints)で入手できます。[チェックポイントでの同期ガイド](/blog/ja/blocknet-checkpoints-fast-sync/)で使用方法を説明します。
2. **同期完了を待つ。** `[sync] progress`が100%になります。ノードはチェーンに追いついてからテンプレートを提供します。
3. **daemonモードでseineを起動。**

   ```sh
   ./seine --mode daemon
   ```

   独自構成ではAPIとcookieの場所を指定します。

   ```sh
   ./seine --mode daemon --api-url http://127.0.0.1:8332 --cookie /path/to/api.cookie
   ```

[ソロ採掘ガイド](https://github.com/zpalmtree/seine/blob/master/docs/guides/solo-mining.md)はウォレットパスワードと独自設定を扱い、[seineの採掘ガイド](https://seineminer.com/ja/blog/how-to-mine-blocknet/)は入手から最初のシェアまでを説明します。Windows、macOS、Linux用の[seineをダウンロード](https://seineminer.com/ja/#download)できます。

## どちらを選べばよいですか？

自分の速度と[ダッシュボード](/)の現在のネットワーク速度で計算し、平均発見間隔を確認します。

- **bntpool.comから始める:** デスクトップ、ノートPC、少数サーバーの場合や、ノードなしで定期的な支払いが欲しい場合です。起動してアドレスか`@name`を入力し標準プールを選びます。
- **ソロを選ぶ:** ネットワークの大きな割合を持ち、自力で頻繁に発見でき、同期済みの自分のノードを運用しているか運用したい場合です。

seineなら後で簡単に選び直せます。両方式は同じダウンロードを使うため、ハードウェアを増やしたら一つのオプションと再起動で切り替えられます。プール採掘中にローカルノードを動かす場合、seineはプール残高の隣にノードのウォレット残高も表示します。

<Note>
[blocknetcrypto.com](https://blocknetcrypto.com/#faraday)によると、Blocknetは2027年2月16日ごろにFaraday更新を計画し、proof of workの変更を予定しています。seineを最新に保ってください。起動時と12時間ごとに新リリースを確認します。
</Note>
