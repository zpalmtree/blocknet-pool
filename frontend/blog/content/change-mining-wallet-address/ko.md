이전 보상 기록을 유지하면서 앞으로의 작업 수신 대상을 바꾸세요. bntpool.com에 이미 연결된 seine 환경을 다룹니다. 첫 연결은 [풀 가이드](/blog/ko/mine-blocknet-on-bntpool/), 새 지갑은 [지갑 가이드](https://seineminer.com/ko/blog/blocknet-wallet-for-mining/)를 참고하세요.

## 채굴 주소는 어떻게 바꾸나요?

<Answer>
한 채굴기를 중지하고 저장 파일이나 평소 명령에서 수신 주소를 갱신한 뒤 재시작합니다. 확인된 전체 주소와 승인된 셰어를 점검하고 bntpool.com에서 주소를 조회합니다. 다른 장치에도 반복하세요. 이전 셰어와 보상은 기록 당시 주소에 남습니다.
</Answer>

*새 작업은 두 번째 지갑으로 향하고 이전 보상 기록은 첫 지갑에 연결됩니다.*

## 변경 전에 두 수신 대상을 기록하기

새 주소는 사용할 지갑에서 직접 복사하세요. 채굴기에는 공개 수신 주소나 등록된 Blocknet ID만 필요하며 복구 문구나 개인 키는 필요하지 않습니다. 이전 풀 활동의 조회 키인 원래 전체 주소도 보관하세요.

이전 주소의 내 통계에서 대기 보상, 확정 잔액, 최근 지급과 활성 장치 이름을 기록하세요. 전환 시 비교 기준이며 새 페이지에는 옛 기록이 포함되지 않습니다. 남은 보상과 지급을 추적하는 동안 원래 지갑에 접근할 수 있어야 합니다.

## 한 채굴기와 시작 명령 변경하기

채굴기를 멈추고 평소 시작 방법을 확인하세요. 기존 설정에서는 `--address`가 저장 주소보다 우선하지만 파일을 바꾸지는 않습니다. PowerShell 예시는 이번 실행의 대상을 선택합니다. `@yourname`을 새 ID나 전체 주소로 바꾸고 검증한 풀, 데이터 경로, 하드웨어 인수는 유지하세요.

```powershell
.\seine.exe --address "@yourname"
```

Linux나 macOS에서는 평소 디렉터리에서 아래 구문을 사용하세요. 두 예시 모두 실제 채굴을 시작하므로 해당 OS용을 선택합니다. 기존 설치가 나머지 연결 설정을 제공합니다. 새 주소에서 셰어를 구분할 수 있게 장치 이름을 유지하세요.

```sh
./seine --address "@yourname"
```

## 정상 재시작에서도 새 주소 사용하기

중지 상태에서 `seine.config.json`의 `address`를 수정하세요. 다른 필드와 유효한 JSON을 유지합니다. `./seine-data`는 작업 폴더 기준 상대 경로이며 `--data-dir`가 다른 위치를 선택할 수 있습니다. 평소 시작에 실제로 쓰이는 파일을 편집하세요.

바로 가기, 스크립트, 예약 작업, 서비스의 오래된 `--address`를 갱신하거나 제거하세요. 수동 명령 성공이 다른 시작 방법을 갱신하지는 않습니다. 정상적으로 재시작해 다시 확인하세요. [설정 가이드](https://seineminer.com/ko/blog/configure-seine-miner/)는 우선순위와 작업 폴더 변경 시 다른 파일을 읽는 이유를 설명합니다.

## Blocknet ID를 사용하면 무엇이 다른가요?

seine v0.2.36은 시작할 때 `@name`을 주소로 확인하고 검증합니다. 전체 주소는 풀 재연결을 포함해 그 실행 동안 고정됩니다. 이름의 연결 주소를 바꾸면 각 채굴기를 재시작하고 수신 대상을 확인하세요. 기존 프로세스의 재연결만으로는 이름 조회를 반복하지 않습니다.

읽기 쉬운 이름이 같아도 이전과 새 전체 주소를 기록하세요. 회계는 확인된 주소를 따르므로 이름 연결 변경이 옛 셰어나 잔액을 보내주지는 않습니다. 이름을 확인할 수 없다면 연결 정보를 점검하거나 지갑에서 검증한 전체 주소를 명시적으로 사용하세요.

## 모든 컴퓨터를 새 주소에서 확인하기

수신 대상과 승인된 제출을 확인한 뒤 내 통계에서 새 전체 주소를 조회하세요. 장치 이름과 최근 셰어를 대조합니다. 새 해시레이트 추정에는 작업과 시간이 필요하므로 셰어 도착부터 확인하세요. [통계 가이드](/blog/ko/track-your-miner-on-bntpool/)는 카운터와 표시되지 않는 장치를 설명합니다.

첫 컴퓨터 확인 후 나머지도 바꾸세요. 고유 이름은 점검을 쉽게 합니다. 오래된 시작 설정이 나중에 옛 대상을 복원하지 않도록 모든 정상 시작 경로를 시험하세요. [여러 컴퓨터 가이드](/blog/ko/mine-multiple-computers-one-wallet/)는 하나의 수신 주소 아래 장치 정리를 설명합니다.

## 이전 주소의 보상은 어떻게 되나요?

기존 적립과 지급은 옛 주소에 남습니다. 이전 유효 셰어는 해당 PPLNS 구간에 계속 기여할 수 있으며 대기 블록 보상은 확인 규칙을 따릅니다. 해시레이트가 0이어도 회계 완료를 뜻하지 않습니다. [PPLNS](/blog/ko/how-pplns-payouts-work/)와 [확인 가이드](/blog/ko/block-confirmations-mining-rewards/)에서 작업, 성숙 중인 보상, 지급을 구분하세요.

수신 대상 변경은 잔액을 합치거나 최소 지급액을 우회하지 않습니다. 현재 규칙과 양쪽 페이지를 확인해 남은 금액을 파악하세요. 장치 이름 변경도 보상을 옮기지 않습니다. 마지막으로 의도한 모든 채굴기가 새 주소로 새 작업을 보내는지 확인하고 이전 지갑과 기록을 보관하세요.
