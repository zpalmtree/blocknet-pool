수신 지갑 하나를 유지하면서 bntpool.com에 두 번째 컴퓨터를 추가하세요. 각 환경에 이름을 붙여 개별 확인한 다음 공통 주소를 관찰합니다. 이 가이드는 추가 절차와 중복 이름을 다룹니다. 첫 채굴기는 먼저 [풀 설정 가이드](/blog/ko/mine-blocknet-on-bntpool/)를 완료하세요.

## 여러 컴퓨터가 같은 지갑으로 채굴할 수 있나요?

<Answer>
네. 각 컴퓨터에서 같은 수신 주소와 서로 다른 장비 이름으로 seine을 실행하세요. bntpool.com은 주소별로 작업과 보상을 기록하고 이름으로 통계 활동을 구분합니다. 합산 주소 화면에 의존하기 전에 각 장비의 승인된 셰어를 확인하세요.
</Answer>

*서로 다른 컴퓨터가 풀을 통해 하나의 수신 주소로 작업을 보내며 각자 이름을 유지하는 그림.*

## 수신 주소와 이름 정하기

지갑 수신 주소나 그 주소를 가리키는 Blocknet ID를 사용하세요. 각 채굴기에서 해석된 실제 주소를 확인합니다. 이름은 입력을 쉽게 하지만 회계는 결과 주소를 따릅니다. ID 대상을 변경해도 실행 중인 채굴기는 다시 시작할 때까지 이전 주소를 유지할 수 있습니다. 이미 얻은 보상은 원래 주소에 남습니다.

[채굴용 지갑 가이드](https://seineminer.com/ko/blog/blocknet-wallet-for-mining/)가 주소 받는 법을 설명합니다. 장비에는 이 공개 수신 정보만 필요하며 복구 구문과 개인 키는 지갑과 함께 보관하세요. `desktop-01`, `server-02`처럼 짧은 이름을 선택합니다. 풀은 앞뒤 공백을 지우고 최대 64자를 유지하므로 긴 이름의 구별 부분은 앞에 두세요.

## 두 번째 채굴기를 고유 이름으로 추가하기

두 번째 컴퓨터에 맞는 seine 릴리스를 설치하고 압축을 푼 폴더에서 실행하세요. 첫 PowerShell 예시는 수신 이름, 풀, 장비를 명시합니다. 실행 전에 `@yourname`을 자신의 ID나 전체 주소로 바꾸세요. 따옴표를 유지하고 해당 장비에서 확인한 백엔드나 조정 옵션을 추가합니다.

```powershell
.\seine.exe --address "@yourname" --pool-url stratum+tcp://bntpool.com:3333 --pool-worker desktop-01
```

Linux나 macOS에서는 아래 명령의 프로그램을 다른 장비 이름으로 실행하세요. 운영체제는 달라도 되지만 수신 주소는 같아야 합니다. 각 예시는 실제 채굴을 시작합니다. 해당 컴퓨터에서 적절한 예시를 실행하고 정상 시작과 조정을 기다리세요. 한 컴퓨터에서 두 예시를 모두 실행할 필요는 없습니다.

```sh
./seine --address "@yourname" --pool-url stratum+tcp://bntpool.com:3333 --pool-worker server-02
```

## 어떤 설정을 공유하나요?

수신 주소와 풀 접속점을 공유합니다. 로컬 데이터 폴더와 이름은 설치마다 따로 유지하세요. seine은 데이터 디렉터리의 `seine.config.json`에 연결을 저장하며 기본 `./seine-data`는 시작 폴더에 따라 달라집니다. 다른 폴더에서 시작하면 다른 설정을 찾을 수 있으므로 고정 위치가 관리하기 쉽습니다.

첫 컴퓨터의 설정을 복사했다면 두 번째 시작 명령에 별도 이름을 지정하고 시작 정보를 확인하세요. 명령줄 덮어쓰기는 이미 저장된 이름을 바꾸지 않으므로 이후에도 명시적인 이름을 유지합니다. 하드웨어 선택은 장비에 맞추고 로컬에서 조정하도록 하세요. 주소 인수는 지급 대상, 이름 인수는 표시 이름입니다. 위 예시처럼 별도로 입력하세요.

## 두 컴퓨터의 기여를 확인하려면?

bntpool.com의 My Stats에서 공통 주소를 조회하세요. 두 이름과 각각의 최근 셰어를 찾습니다. 로컬 채굴기에서도 승인된 제출을 확인하세요. 한 컴퓨터씩 보면 프로세스를 풀의 행과 연결할 수 있어 총 해시레이트만 볼 때보다 오류를 찾기 쉽습니다.

풀은 제출된 셰어로 해시레이트를 추정하므로 새 장비는 의미 있는 수치까지 시간과 승인 작업이 필요할 수 있습니다. 로컬 속도와 풀 추정치는 측정 방법과 기간이 다릅니다. 최근 셰어와 승인 횟수로 활동부터 확인한 뒤 긴 기간을 비교하세요. [통계 가이드](/blog/ko/track-your-miner-on-bntpool/)는 연결 수로 장치 수를 추측하지 않고 카드와 행을 설명합니다.

## 장비가 없거나 이름이 같으면 어떻게 하나요?

같은 주소에서 이름이 같으면 기록된 셰어가 묶입니다. 한 채굴기의 이름 옵션을 바꾸고 다시 시작하세요. 새 제출은 새 이름을, 과거 기록은 이전 이름을 유지합니다. 과거 셰어가 보고 기간에 있으면 옛 행이 남을 수 있습니다. 이름 변경은 주소의 기존 잔액을 옮기지 않습니다.

보이지 않는 장비는 실제 해석된 주소, 접속점, 이름을 열린 페이지와 비교하세요. 연결과 승인 셰어도 확인합니다. 하나의 seine 프로세스 안에서 CPU와 GPU는 이 설정에 별도 이름이 필요하지 않습니다. 거절되거나 오래된 셰어는 주소를 반복 변경하지 말고 [셰어 상태 가이드](/blog/ko/accepted-rejected-stale-shares/)를 따르세요.

## 보상과 지급은 어떻게 합산되나요?

컴퓨터의 유효한 작업은 같은 주소의 PPLNS 기간 참여에 기여합니다. 이름은 기여를 추적할 뿐 별도 잔액을 만들지 않습니다. 추가 장비는 실제 제출한 유효 작업을 더하며 장비나 이름당 고정 보상을 주지 않습니다. 하드웨어와 가동 시간에 따라 기여가 다르고 이름만 늘려도 작업은 늘지 않습니다.

[PPLNS 가이드](/blog/ko/how-pplns-payouts-work/)가 블록 발견 시 분배를 설명합니다. 확인과 지급 규칙은 합산 주소 잔액에 계속 적용됩니다. 지갑을 합치거나 이름 사이에 잔액을 옮길 필요가 없습니다. 계속 실행하기 전에 각 장비의 수신 대상, 다른 이름, 승인 셰어를 확인하세요. 다음 컴퓨터에도 이 짧은 목록을 사용합니다.
