保留一個收款錢包，同時為 bntpool.com 加入第二台電腦。替各安裝環境命名、分別核對，再監控共用位址。本指南介紹新增機器與處理重名的方法。第一台礦工請先完成[礦池設定指南](/blog/zh-hant/mine-blocknet-on-bntpool/)。

## 多台電腦能向同一錢包挖礦嗎？

<Answer>
可以。在各電腦使用相同收款位址與不同機器名稱執行 seine。bntpool.com 按位址記錄工作與獎勵，名稱則區分統計活動。在依賴位址總覽之前，先確認每台機器都有已接受的份額。
</Answer>

*不同電腦透過礦池向一個收款位址提交工作，各自保留獨立名稱。*

## 選擇收款位址與命名方式

使用錢包收款位址，或解析到該位址的 Blocknet ID。讓礦工持續運作前，檢查各機器解析出的位址。名稱方便輸入，但記帳依據是最終位址。變更 ID 指向後，現有挖礦程序可能在重新啟動前保留舊解析結果；已獲得的獎勵仍屬於原位址。

[挖礦錢包指南](https://seineminer.com/zh-hant/blog/blocknet-wallet-for-mining/)說明如何取得位址。機器只需要公開的收款目標，復原詞組與私密金鑰留在錢包端。選擇 `desktop-01`、`server-02` 等簡短名稱。礦池會去除前後空白，最多保留 64 個字元，因此把區別部分放在長名稱開頭。

## 用獨立名稱加入第二台礦工

在第二台電腦安裝適合的 seine 版本，從解壓縮資料夾執行。第一個 PowerShell 範例明確指定收款名稱、礦池與機器名。執行前將 `@yourname` 換成自己的 ID 或完整收款位址，保留引號，並視需要加上這台機器已驗證的後端或調校選項。

```powershell
.\seine.exe --address "@yourname" --pool-url stratum+tcp://bntpool.com:3333 --pool-worker desktop-01
```

Linux 或 macOS 使用下方指令的程式與另一個機器名稱。作業系統可以不同，收款位址應一致。每個範例都會開始實際挖礦。只在對應電腦執行適合的範例，等待正常啟動與調校完成，不必在同一台機器執行兩個範例。

```sh
./seine --address "@yourname" --pool-url stratum+tcp://bntpool.com:3333 --pool-worker server-02
```

## 哪些設定由電腦共用？

共用收款位址與礦池連線端點，但各安裝環境保留獨立本機資料夾與名稱。seine 將連線儲存在資料目錄的 `seine.config.json`；預設 `./seine-data` 取決於啟動資料夾。從其他目錄執行可能找到另一套設定，固定啟動位置較易維護。

若複製第一台電腦的設定，請在第二台的啟動指令指定不同名稱，並在啟動資訊確認。日後指令也保留明確名稱：命令列覆寫不會改寫已儲存的名稱。硬體選項應符合各電腦，讓它在本機調校。位址引數決定收款目標，名稱引數決定顯示標籤，依範例分別輸入。

## 如何確認兩台電腦都有貢獻？

在 bntpool.com 開啟 My Stats，查詢共用收款位址。檢查兩個名稱與各自最近的份額，也在各礦工確認已接受的提交。一次核對一台電腦，把本機程序對應到礦池資料列，比只看總雜湊率更易發現錯誤。

礦池依提交份額估算雜湊率，新機器可能需要時間與已接受的工作才有具參考性的讀數。本機速率與礦池估值使用不同測量及時間範圍。先以最近份額和接受計數確認活動，再比較較長時間。[統計指南](/blog/zh-hant/track-your-miner-on-bntpool/)解釋卡片與資料列，不必從連線總數推測裝置數。

## 機器不見或名稱相同時怎麼辦？

同一位址下使用相同名稱，會把記錄的份額合併。用名稱選項重新命名其中一個礦工並重新啟動。新提交使用新標籤，舊紀錄保留原標籤。歷史份額還在報告期間內時，舊列可能持續顯示。改名不會移動位址已獲得的餘額。

對未顯示的機器，將實際解析位址、端點與名稱和正在查看的頁面比較，再檢查連線與已接受份額。同一 seine 程序中的 CPU 和 GPU 在此設定不必分別命名。遇到拒絕或過時份額，依[份額狀態指南](/blog/zh-hant/accepted-rejected-stale-shares/)排查，不要反覆更換錢包位址。

## 合併獎勵與付款如何運作？

各電腦的有效工作共同計入同一位址在 PPLNS 視窗中的參與量。名稱有助追蹤貢獻，不建立獨立餘額。新增機器增加的是實際提交的有效工作，不是每台裝置或每個名稱的固定獎勵。硬體與運作時間不同，貢獻也可能不同；只增加名稱不會增加工作。

[PPLNS 指南](/blog/zh-hant/how-pplns-payouts-work/)解釋礦池找到區塊時的分配方式。確認與付款規則仍適用於位址的合併餘額。不必合併錢包，也無需在機器名稱間轉移餘額。持續運作前，逐台確認收款目標、獨立名稱與已接受份額，下次新增時沿用這份清單。
